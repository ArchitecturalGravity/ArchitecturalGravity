[Review]:

=> For each relevant string or screen:
  - Compare [LocalizedStrings] against [SourceStrings]
  - Check applicable items in [ReviewChecks]
  - Use [Termbase] to verify product terminology
  - Record the exact string key or screen reference for any finding
=> Classify each finding by:
  - User impact
  - Reproducibility
  - Affected flow
  - Whether the defect is linguistic or functional
=> Preserve a distinction between translation defects and product defects
=> Append any check that cannot be evaluated from the available evidence to [BlockedChecks]

[Gate]:
=> Block release for a finding that changes transaction meaning or prevents completion of a [CriticalFlows] step
=> Block release for broken placeholders or markup that corrupts user-visible content
=> Do not block release solely for a stylistic preference without an approved terminology or style requirement
=> Store the supported release recommendation and its evidence in [ReleaseAssessment]
=> Keep unresolved evidence gaps explicit
